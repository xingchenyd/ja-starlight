# 星光伙伴与独立业务运营

状态：实现与本地验收；独立分支，不合并 main，不发布校园功能至生产。

采用 [Spec Kit](https://github.com/github/spec-kit) 的规格、计划、任务和验证组织方式。未执行 CLI 初始化或覆盖现有项目配置。

## 已确认的业务边界

1. 只有平台技术负责人持有唯一管理密钥；不启用二次验证。业务人员不共享密钥。
2. 校外总项目负责人使用独立 operator 账号，不冒充学生、不绑定学校。
3. 星光伙伴保留 student 身份，能够正常报名、组队、参赛和记录成长。
4. 校园权限由技术负责人主动任命，覆盖本校全部学生；以核验后的学校关系控制，不信任简历或请求里的学校名称。
5. 学生主动申请学校归属；星光伙伴核验本校申请，不能核验自己。没有伙伴的学校由技术负责人核验。
6. 校园活动和内容提交独立审核；项目负责人可直接发布平台官方内容。发布人和最后编辑人均不得审核本人提交。
7. 本校学生列表只含必要学籍与参与统计。报名回答仅向活动实际主办方开放；不得读取他人的私密简历。
8. 伙伴任命即自动生成认证任职经历，不设置人工完成验收。撤职立即取消有效标识与管理权限，保留任职历史。
9. 校园资源归学校，换任伙伴仍可管理历史发布与报名；企业仍只审核本企业活动报名。

## 角色

| 身份 | 学生功能 | 本校管理 | 平台业务 | 系统安全 |
| --- | --- | --- | --- | --- |
| 学生 | 全部原有能力 | 申请学校归属 | 无 | 无 |
| 星光伙伴 | 保持全部能力 | 本校核验、发布、活动报名与竞赛成果 | 另行授权后可审核 | 无 |
| 内容审核员 | 如原为学生则保留 | 另行任命后才有 | 活动/内容审核、退回、移除 | 无 |
| 项目负责人 | 根据基础账号身份 | 运营汇总，不自动读取全校私密信息 | 主体核验、官方发布、官方活动报名与成果、内容审核 | 无 |
| 唯一技术负责人 | 不伪造学生身份 | 学校创建、兜底学籍核验、任命/撤销 | 保留应急治理能力 | 唯一密钥与日志 |

## 验收条件

- 普通学生、企业、校外运营账号均不能自行任命；学生报名流程兼容旧版。
- A 校伙伴不能读取 B 校成员、发布或报名；猜测记录 ID 不能越权。
- 同一伙伴可参与活动，但不能批准自己的报名或评审自己的参赛团队。
- 审核员不能使用管理密钥 API，不能读取私密简历和非本方报名。
- 任命与经历生成、撤职与认证取消成组写入；数据保存在服务器适配器的 SQLite 中，重启仍可读取。
- 邀请使用随机一次性令牌，数据库只存哈希，七日失效；重复激活不得创建第二个用户。
- 旧密钥与旧会话失效；旧多人密钥创建/恢复 API 关闭。
- 原活动问卷保留提交时题目快照；校园活动复用同一报名校验与成果流程。
