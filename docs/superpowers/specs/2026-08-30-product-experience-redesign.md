# JA 星光计划全平台产品体验与动效重构设计

状态：待用户逐模块审核
日期：2026-08-30
适用项目：JA Star Plan 星光计划正式平台

## 1. 项目目标

本轮在不改变平台核心定位的前提下，将现有公共主页、学生端、企业端与 JA 运营后台从“功能可演示”升级为流程明确、反馈完整、视觉统一、可长期维护的正式产品。

核心目标：

- 完善已确认的所有现有功能，不通过堆叠页面制造“功能丰富”的假象。
- 建立统一的设计组件、动效规则、加载与错误反馈。
- 让学生、企业、JA 三端共享同一品牌语言，但保持不同角色的任务重点。
- 让页面地址、浏览器前进后退、刷新恢复和深链接符合正式网站习惯。
- 新增收藏、活动日历、发布排期、版本历史、JA 角色权限和高级数据分析。
- 为未来正式域名、自有服务器、腾讯云邮件及移动端适配保留稳定接口。

## 2. 本轮范围与明确排除项

### 2.1 本轮范围

1. 全站设计系统与动效基础。
2. 公共主页和公开目录。
3. 学生端五个模块及通知中心。
4. 企业端七个模块及发布、报名闭环。
5. JA 后台审核、发布、认证、排序、互动、诚信、权限与审计。
6. 新增收藏、活动日历与提醒、发布排期、版本历史、JA 角色权限、高级数据分析。
7. URL 导航、状态反馈、可访问性、性能和端到端测试。

### 2.2 本轮不做

- 不开发 PWA、手机桌面入口或原生 App。
- 不在本轮专门重做手机版界面；但新组件不得继续使用阻碍后续响应式适配的固定宽高和桌面专属逻辑。
- 不增加站内聊天或学生与企业私信。
- 不增加站内岗位申请流程；岗位继续展示企业简历邮箱，由学生自行发送。
- 不增加长沙以外城市导航，公开机会不增加城市筛选。
- 不在公共主页显示 JA 后台入口。
- 不引入与核心流程无关的积分、排行榜、社交动态或游戏化功能。

## 3. 产品与视觉原则

### 3.1 信息层级

- 页面一级标题使用中文大标题，可保留一行简洁英文，但不重复解释中文。
- 删除装饰性小字、演示性说明和“平台使用提示”。
- 日期、发布方、状态、错误、字段帮助、隐私说明属于业务信息，必须保留并使用至少 14px 的清晰字号。
- 每个页面只能有一个视觉主操作；其他操作降为次级、文字或溢出菜单。
- 红色仅用于危险、删除和错误；常规强调使用 JA 青、深蓝、绿色和黄色。

### 3.2 品牌表现

- 公共主页允许使用更丰富的官方活动图片、大幅渐变、图片裁切和较明显的品牌动效。
- 学生端使用亲和、清晰、鼓励成长的视觉语气。
- 企业端使用高信息密度、结果导向、可信和高效的视觉语气。
- JA 后台使用稳定、克制、审计明确的运营工具语气。
- 官方图片可作为低透明度图层或局部视觉锚点，但不得覆盖表单、数据表和审核正文。

### 3.3 统一动效令牌

建立全局 motion tokens，所有组件禁止自行写任意时长。

| 令牌 | 时长 | 用途 |
|---|---:|---|
| instant | 0ms | 聚焦、无动效模式 |
| micro | 90ms | 按下、切换选中状态 |
| quick | 140ms | 悬停、提示出现、退出 |
| standard | 220ms | 下拉、卡片、局部内容进入 |
| panel | 280ms | 弹窗、侧栏、筛选展开 |
| page | 340ms | 工作台模块切换 |
| story | 600ms | 主页和活动大图切换 |

缓动：

- 进入：`cubic-bezier(0, 0, 0.3, 1)`。
- 标准状态变化：`cubic-bezier(0.2, 0, 0.38, 0.9)`。
- 退出：`cubic-bezier(0.2, 0, 1, 0.9)`，退出时间比进入短。
- 禁止弹跳、橡皮筋和大面积持续漂浮。
- 动画属性优先使用 `transform`、`opacity` 和颜色；禁止高频动画 `width`、`height`、`top`、`left` 和模糊滤镜。

### 3.4 页面切换规则

- 左侧导航和顶部问候保持固定，不随模块重新播放。
- 同级栏目切换：旧内容 120ms 淡出，新内容从右侧 20px 进入并淡入，总时长不超过 340ms。
- 返回上一级：内容从左侧轻微进入，帮助用户理解导航方向。
- 列表进入详情：封面、标题或企业 Logo 使用共享元素过渡；不支持 View Transition API 时退化为普通淡入。
- 弹窗从触发对象附近缩放进入；右侧详情面板从右侧进入。
- 页面切换后焦点移动到新页面一级标题；保留每个栏目独立滚动位置。
- 浏览器返回、前进和刷新必须恢复当前栏目、筛选条件和打开的详情对象。

### 3.5 减少动态效果

- 响应系统 `prefers-reduced-motion`。
- 减少动效模式下取消位移、缩放、自动轮播和背景持续动画，仅保留不超过 100ms 的颜色或透明度提示。
- 功能不能依赖动画完成；关闭动画后所有按钮、弹窗、轮播和表单仍可用。

## 4. 组件与代码架构重构

### 4.1 现状问题

- `app/globals.css` 超过一万行，存在多轮样式刷新叠加。
- 学生/企业端集中在一个超大组件文件，发布器、报名表、弹窗和业务页面耦合。
- JA 后台同样包含审核、发布、认证、分析和密钥管理等多个职责。
- 页面存在正式账号体系与 `demo` 命名、请求头残留并存的历史痕迹。

### 4.2 目标结构

建立以下边界：

- `app/components/ui`：Button、IconButton、Input、Select、Range、Card、Badge、Tabs、Accordion、Dialog、SidePanel、Toast、Skeleton、EmptyState、DataTable、Uploader、Stepper。
- `app/components/motion`：PageTransition、Presence、StaggerList、SharedElement、ReducedMotionProvider。
- `app/components/publishing`：发布步骤、媒体上传、内容块编辑、报名字段编辑、实时预览、审核状态。
- `app/components/catalog`：岗位、活动、内容公共卡片和筛选器。
- `app/workspace/student/*`：学生各模块。
- `app/workspace/enterprise/*`：企业各模块。
- `app/ja-console/*`：JA 各模块。
- `lib/services`：收藏、日历、发布排期、版本、分析和通知服务。

UI 组件只处理交互和展示；数据请求、权限和业务规则放在服务/API 层。学生、企业和 JA 发布器共用编辑器内核，不复制三套相似代码。

## 5. 全局组件详细设计

### 5.1 按钮

变体：Primary、Secondary、Tertiary、Ghost、Danger、Icon。

每个按钮具有：default、hover、focus-visible、pressed、loading、success、error、disabled 状态。

- 标签使用“动词＋对象”：保存草稿、提交审核、导出报名数据。
- 加载时保持原宽度，显示进度图标并禁用重复提交。
- 成功时显示勾选和短文案 1.2 秒；失败后恢复按钮并在附近显示错误。
- 禁用按钮如果原因不明显，不直接灰掉；改为保持可聚焦并说明缺少的条件。
- 点击区域桌面端不小于 40px 高，为后续移动端预留 44px 触控尺寸。

### 5.2 表单

- 标签始终可见，不使用占位符代替标签。
- 失焦时完成字段校验，提交时在顶部给出错误摘要并定位第一个错误。
- 长表单自动保存草稿，顶部显示“正在保存 / 已保存 / 保存失败”。
- 离开未保存表单时提示保存草稿、放弃修改或继续编辑。
- 已填写的企业资料、学生资料自动预填，避免重复输入。

### 5.3 加载、空状态与错误

- 首次列表加载使用与最终结构相同的骨架屏。
- 单个按钮操作使用按钮内部加载，不使用全屏遮罩。
- 空状态必须说明“为什么为空”和“下一步能做什么”。
- 网络失败保留当前内容，显示非阻塞错误条及重试按钮。
- 删除、撤回、批量退回等操作必须有确认和撤销窗口。

### 5.4 弹窗和侧栏

- 简短确认使用 Dialog。
- 包含详情、审核、报名表和多字段编辑的内容使用右侧 SidePanel。
- 打开后焦点进入容器，关闭后返回原触发按钮。
- 支持 Escape 关闭；存在未保存内容时 Escape 先触发离开确认。
- 背景锁定滚动，面板自身滚动。

### 5.5 数据表

- 工具栏包含搜索、筛选、刷新、导出、列设置和主操作。
- 表头支持排序；筛选条件以可删除标签展示。
- 勾选行后出现批量操作条，并隐藏冲突的单行操作。
- 行详情优先使用右侧面板；补充信息较少时可行内展开。
- 大数据使用分页和服务端筛选，不一次读取全部记录。

## 6. 公共主页与公开内容

### 6.1 顶部区域

- 保留 JA 星光计划 Logo、主标题和学生/企业两个入口。
- 不显示 JA 后台入口，不使用“公开体验”“演示”等词。
- 主视觉使用 JA 官方图片与品牌渐变，动画仅首次进入播放一次。
- 学生入口与企业入口采用同一尺寸、不同强调级别，不制造角色优劣。

### 6.2 横向故事轮播

- 数据来自所有已审核、已到公开时间且未下线的推荐活动和成长内容。
- 不再将动态内容限制为 5 条，也不在有真实数据时混入无关示例。
- 每张停留 5 秒，切换 600ms，循环播放。
- 提供上一张、下一张、暂停/继续和当前序号。
- 鼠标悬停暂停；键盘焦点进入后暂停且不自动恢复，除非用户点击继续。
- 点击封面直达准确活动或内容详情。
- 封面加载失败时显示品牌占位图，不拉伸图片。

### 6.3 三类内容栏目

1. 实习项目机会：显示企业 Logo、企业名称、岗位名称、摘要、薪资和发布时间。
2. 成长活动：显示真实封面、活动名称、发布方和时间。
3. 成长内容：显示文章或视频封面、主题、摘要和预计阅读/观看时间。

每栏只展示 3 条，并有“查看全部”。排序严格使用 JA 运营排序、推荐和发布时间规则。

### 6.4 公开目录和详情

- 公开目录可匿名浏览，筛选条件进入 URL。
- 企业名称进入企业公开主页，展示该企业全部有效岗位、活动和内容。
- 详情页保留分享链接、返回目录和相关内容。
- 下线、审核中或不存在的内容使用明确状态页，不能只显示空白。

## 7. 学生端详细设计

### 7.1 全局框架

- 左侧：总览、实习项目机会、成长活动、成长内容、成长主页；底部仅保留联系项目团队和退出登录。
- 顶部固定显示“你好，姓名”、通知入口和同步状态，不显示角色切换。
- 每个栏目拥有稳定 URL，例如 `/workspace/student/opportunities`；旧查询地址兼容跳转。

### 7.2 学生总览

布局顺序：

1. 最近 5 条实习项目机会。
2. 最近 3 条成长活动。
3. 最近 3 条成长内容。
4. 个人成长时间轴预览。

- 每个板块有“查看全部”。
- 卡片点击进入准确记录，不只切换栏目。
- 时间轴显示真实日期、活动/经历名称、JA 认证标识和产出摘要，不使用抽象柱状图。
- 总览首次进入采用轻量分组显现，之后切换不重复大幅动画。

### 7.3 实习项目机会

筛选器采用可展开栏目：

- 岗位类别。
- 学历要求：高中、大专、本科、硕士、博士。
- 薪资区间：双端滑块，1 元/天为步长，0–500 元/天。
- 行业分类：已确认的完整行业列表。

行为：

- 点击筛选栏目后平滑展开，其他栏目可保持打开。
- 当前筛选显示为标签，可单项清除或全部清除。
- 结果数量实时更新，快速输入使用防抖。
- 筛选写入 URL，返回后保留筛选和滚动位置。

岗位卡片：

- 第一层：企业 Logo、带品牌色的企业名称、岗位名称。
- 第二层：一句话岗位摘要。
- 第三层：地点、实习周期、发布时间、薪资区间。
- 底部：联系邮箱、复制邮箱、发送简历、查看详情。
- 企业名称进入企业主页，查看全部岗位。
- 不显示“申请岗位”，不建立站内投递记录。

### 7.4 收藏与稍后查看（新增）

- 学生可收藏岗位、活动和成长内容。
- 收藏按钮使用同一个图标与交互，点击后立即反馈并持久保存。
- 总览新增“我的收藏”入口，但不增加左侧一级导航；收藏页按三类内容分组。
- 内容下线后保留收藏记录并标记“已下线”，允许删除收藏。
- 不对企业公开学生收藏行为。

### 7.5 成长活动

上部：所有有效活动的自动横向轮播；不展示报名字段摘要。
下部：按 JA 排序和发布日期排列的活动列表，每个活动一行，左图右文。

活动详情包含：

- 标题、封面/视频、发布方、日期、地点、名额、截止时间。
- 活动背景、流程、报名要求、学生需填写字段。
- 报名按钮和当前报名状态。

报名流程：

1. 打开右侧报名面板。
2. 自动预填姓名、邮箱、学校等已有资料。
3. 按发布方配置显示动态字段。
4. 字段校验并提交。
5. 显示待审核、已通过、需修改、已取消状态。
6. 企业活动由企业审核，JA 活动由 JA 审核。

### 7.6 活动日历与提醒（新增）

- 报名成功后自动加入学生平台日历。
- 日历入口放在成长活动页面，不增加左侧一级栏目。
- 默认提供月视图和近期列表，显示报名截止和活动时间。
- 通知中心在截止前 24 小时、活动前 24 小时提醒；提醒时间后续可配置。
- 学生可关闭单个活动提醒，但不能修改官方活动时间。
- 本轮只做站内通知，不做短信、微信或系统推送。

### 7.7 成长内容

目录卡片：封面、类型、主题、摘要、预计阅读/观看时间、发布方。
文章详情使用正常图文阅读版式；视频详情以播放器为主，下方显示介绍、章节和附件。

互动：

- 点赞采用即时反馈，失败时回滚并提示。
- 评论提交后显示发送状态，不允许重复提交。
- 学生可删除自己的评论。
- 企业只能回复和管理自己的内容，JA 管理 JA 内容及平台违规内容。
- 回复显示发布方身份，不伪装普通学生。

### 7.8 成长主页

桌面布局：左侧固定资料卡，右侧成长时间轴独立滚动。

左侧：

- 头像、姓名、学校、专业、年级、自我介绍。
- 查看/上传简历按钮。
- 编辑个人资料按钮。
- 不展示简历截图，不重复列出项目经历。

简历流程：

- 仅支持 PDF，上传前显示大小和隐私说明。
- 文件保存在私有对象存储，默认仅学生本人可查看。
- 异步提取姓名、学校、专业、技能、经历和奖项。
- 提取结果先进入确认页面，学生逐项修改后才写入资料。
- 解析失败不影响原文件查看和手动编辑。
- “查看完整简历”使用受权限保护的临时访问地址。

右侧时间轴：

- 平台活动完成后自动加入并显示高亮 JA 认证。
- 学生可手动添加活动、项目、比赛、志愿或其他经历。
- 手动经历支持日期、标题、角色、说明、成果图片和外部链接。
- 自动经历不可删除或伪造，只能调整排序或选择是否公开。
- 支持拖拽排序，同时保留“上移/下移”键盘替代操作。
- 点击节点打开详情，展示做了什么、个人角色和产出。

## 8. 企业端详细设计

### 8.1 企业全局框架

导航：工作台、机会发布、活动发布、内容发布、互动管理、报名数据、企业画像。
顶部固定显示企业名称、通知和认证状态。

- 未认证企业可完善资料和保存草稿，但不能正式提交公开。
- 所有待办、退回原因和审核状态必须可点击直达对应记录。
- 不显示“公开体验”或无实际作用按钮。

### 8.2 企业工作台

首屏只展示需要立即处理的任务：

1. 待审核报名。
2. 被退回的发布内容。
3. 即将开始的活动。
4. 企业认证待补充材料。

第二屏展示：开放岗位、活动、成长内容的状态概览和最近表现。
所有数据基于真实记录，不混入固定演示数字。

### 8.3 统一发布中心

岗位、活动和内容使用同一发布中心外壳，创建时先选择类型。

步骤：

1. 基础信息。
2. 详细内容。
3. 媒体与附件。
4. 展示和报名配置。
5. 预览与提交。

通用能力：

- 30 秒自动保存草稿及失焦保存。
- 每一步显示完成、当前、未开始和错误状态。
- 离开时提示未保存内容。
- 桌面端右侧实时预览学生端最终效果。
- 封面上传完成后只引用正式资源地址，预览和公开页使用同一资源字段。
- 发布状态：草稿、待审核、已通过、已退回、定时、已公开、已下线。

岗位：

- 企业 Logo、岗位名称、岗位类别、学历、行业、薪资上下限、周期、邮箱。
- 岗位职责与能力要求使用结构化段落编辑。
- 企业主体认证通过后岗位可直接公开，但保留风险检测和审计。

活动：

- 封面、视频、日期地点、名额、截止时间、流程和报名要求。
- 可从字段库选择报名字段或新建文本、单选、多选、长文本、文件字段。
- 发布前展示学生报名表完整预览。
- 企业活动提交后进入 JA 审核；学生报名由企业审核。

成长内容：

- 支持文章和视频。
- 内容块包括标题、正文、引用、图集、视频、议程、业务卡片和附件。
- 企业内容提交后进入 JA 审核。

### 8.4 发布排期（新增）

- 发布方可设置立即公开或定时公开。
- 可选设置下线时间；不设置则持续公开。
- 定时记录必须先完成对应审核，审核完成但未到时间时显示“已通过·待上线”。
- 修改已排期内容会生成新版本；重要字段变化需要重新审核。
- 到期下线不删除内容和历史数据。

### 8.5 版本历史与回滚（新增）

- 每次保存草稿、提交审核、审核修改、公开设置变更均生成版本。
- 版本记录作者、时间、状态和变更摘要。
- 企业只能查看自己的版本；JA 可查看审核对象完整版本。
- 支持并排比较当前版本与上一个版本。
- 回滚不是覆盖历史，而是从旧版本创建一个新草稿。
- 已公开内容回滚后必须按内容类型重新判断是否需要审核。

### 8.6 报名数据

顶部指标：总报名、待审核、已通过、需修改、名额使用率。
工具栏：活动筛选、关键词、状态、报名时间、刷新、导出。

表格列：学生、学校/专业、活动、报名时间、完整度、当前状态、操作。
点击行打开右侧详情，分区展示基本资料、动态报名字段、附件和审核历史。

- 单条通过/退回。
- 多选批量通过/退回，批量退回必须填写理由。
- 已处理记录防止重复操作。
- CSV 导出采用当前筛选范围，包含动态字段，并记录导出审计。
- 企业只能读取自己活动的报名；JA 活动报名不出现在企业端。

### 8.7 互动管理

- 按内容、未回复、已回复、已删除分类。
- 显示评论正文、学生、内容标题和时间。
- 支持回复、修改自己的回复、删除不适合公开的评论。
- 删除必须记录原因并写入审计。

### 8.8 企业画像

- 企业 Logo、名称、统一社会信用代码、官网、行业、简介、联系人和认证材料。
- 认证进度清楚展示：未填写、待核验、已认证、需补充。
- 公开主页预览与编辑同屏切换。
- 联系人和认证材料永不出现在公开主页。

### 8.9 企业分析（新增高级分析）

第一阶段指标：

- 岗位浏览与邮箱点击。
- 活动详情浏览、报名人数、通过人数和名额使用率。
- 内容浏览、点赞、评论和回复率。
- 时间范围和内容筛选。

不显示虚构转化率。浏览数据不足时展示明确空状态。支持导出当前图表数据，不在本轮加入复杂归因模型。

## 9. JA 端详细设计

### 9.1 JA 全局框架

导航分组：

- 运营：数据看板、分区审核、内容发布、平台内容。
- 组织：企业认证、互动管理、诚信管理。
- 系统：管理员与权限、审计日志。

顶部显示当前管理员姓名、角色、会话剩余时间和通知。JA 入口继续隐藏于公开主页。

### 9.2 JA 数据看板

首屏：待审核、待认证、即将开始活动、异常/退回事项。
第二屏：岗位、活动、内容、报名、互动的趋势和状态分布。
所有指标可点击进入过滤后的业务列表。

### 9.3 三类审核队列

只建立三个业务审核队列：

1. JA 发起的活动：由 JA 内部审核学生报名。
2. 企业发布的活动：JA 审核公开内容，企业审核学生报名。
3. 企业发布的成长内容：JA 审核后公开。

规则补充：

- JA 发布的成长内容不进入上述公开前审核，拥有发布权限的 JA 人员可直接公开或排期。
- 已认证企业的岗位不进入 JA 内容审核队列。
- JA 活动的“内部审核”指报名审核，不再把 JA 自己的活动内容错误放入企业内容审核逻辑。

队列界面：

- 顶部显示三个队列及数量。
- 支持关键词、发布方、提交时间和风险状态筛选。
- 列表显示封面、标题、提交者、版本、风险提示和等待时间。
- 右侧审核面板同时显示最终公开预览、关键字段和上次退回意见。
- 通过时可设置分类、推荐、排序和公开排期。
- 退回必须选择问题类型并填写具体意见。
- 批量审核仅适用于低风险且同类记录；批量退回必须统一原因。

### 9.4 JA 内容发布

- 共用企业发布器内核。
- JA 可发布活动、文章和视频。
- JA 活动发布后直接公开或排期；后续学生报名进入 JA 报名审核。
- JA 成长内容由具备发布权限的人员直接公开或排期。
- 发布、修改和下线全部进入版本历史和审计。

### 9.5 平台内容排序

- 分岗位、活动、成长内容三个视图。
- 展示公开状态、推荐状态、排序值、上线和下线时间。
- 支持拖拽排序，同时提供键盘上移/下移。
- 排序修改先本地预览，点击保存后一次提交，避免每次拖动立即写数据库。
- 主页三个栏目与学生端使用同一排序服务。

### 9.6 企业认证

- 列表按待核验、已认证、需补充、全部分类。
- 详情展示企业提交资料、认证材料和历史意见。
- 通过或退回均写入审计并通知企业。
- 企业名称、信用代码和认证状态变化进入版本历史。

### 9.7 互动与诚信

- 互动管理集中查看所有评论，但 JA 日常只处理 JA 内容或平台违规事项。
- 企业内容的一般回复仍由企业处理。
- 诚信记录关联账号、企业、活动或内容，包含事实、证据、处理状态和解除记录。
- 诚信记录不得直接公开给学生或其他企业。

### 9.8 JA 管理员角色权限（新增）

角色：

- 超级管理员：全部权限、密钥和角色管理。
- 运营管理员：看板、排序、JA 发布、数据分析。
- 内容审核员：企业活动和内容审核、互动违规处理。
- 企业认证员：企业主体认证。
- 只读审计员：查看数据和日志，不可修改。

规则：

- 管理密钥绑定一个管理员和角色，不再只有一个笼统管理员权限。
- 权限由服务端检查，不能依赖前端隐藏按钮。
- 高风险操作包括撤销管理员、改变角色、批量下线、导出敏感数据，需要二次确认。
- 至少保留一个有效超级管理员。

### 9.9 JA 高级分析（新增）

- 平台活跃趋势：公开内容、报名、互动和活跃账号。
- 活动漏斗：详情浏览、开始报名、提交报名、审核通过、实际完成。
- 内容表现：浏览、点赞、评论和发布方回复。
- 企业贡献：有效岗位、活动、内容和报名处理时效。
- 审核效率：等待时长、通过率、退回原因分布。
- 支持时间、内容类型、发布方和状态筛选及数据导出。
- 数据定义在界面提供说明，避免不同人对同一指标理解不一致。

## 10. URL、状态和通知设计

### 10.1 路由

- 每个一级栏目拥有独立可分享地址。
- 详情对象使用路径或 `item` 参数，刷新后继续打开同一对象。
- 筛选、排序和分页写入 URL；临时表单内容不写入 URL。
- 旧 `/workspace?role=...&tab=...` 地址继续兼容并跳转到新地址。

### 10.2 通知中心

通知类型：

- 报名提交、通过、退回、取消。
- 内容提交、通过、退回、定时上线、下线。
- 企业认证结果。
- 评论回复。
- 活动截止和开始提醒。
- 管理员权限或密钥状态变化。

每条通知必须关联明确对象和目标地址。通知列表支持未读、全部、按类型筛选和全部已读。

## 11. 数据模型增量

新增或扩展以下数据结构，具体字段在实施计划中落实：

- `favorites`：用户、对象类型、对象 ID、创建时间，唯一约束防止重复收藏。
- `calendar_events`：学生、来源对象、开始/结束、提醒设置、状态。
- `notifications`：扩展通知类型、对象引用和去重键。
- `publication_schedules`：记录版本、上线/下线时间、执行状态和错误。
- `record_versions`：对象、版本号、完整快照、作者、变更摘要、来源版本。
- `admin_roles`、`admin_permissions`、`admin_role_assignments`。
- `analytics_events`：最小化事件、对象、匿名会话/用户、时间和必要上下文。
- `analytics_daily_rollups`：按日聚合，避免看板实时扫描全部事件。

隐私规则：

- 收藏只对学生本人可见。
- 简历和报名资料不进入分析事件。
- 企业只能分析自己发布的对象。
- JA 导出敏感数据需要权限并记录审计。

## 12. 排期与后台任务

- 当前托管环境使用定时任务检查待上线、待下线内容和提醒通知。
- 任务必须幂等，同一排期或提醒重复执行不会重复公开或重复通知。
- 失败记录错误和重试次数，JA 后台显示异常任务。
- 未来迁移服务器时保持同一 `Scheduler` 接口，替换具体定时执行器。

## 13. 安全、可靠性与迁移

- 所有业务权限以现有正式会话为基础，删除客户端 `demo` 身份命名和无效请求头残留。
- 上传文件校验类型、大小、所有者和访问权限；简历始终私有。
- 发布、审核、报名、导出、角色和版本操作全部记录审计。
- 重要写入使用版本号避免多人编辑覆盖；冲突时显示比较并允许重新应用修改。
- 数据库迁移只新增兼容表和索引，不破坏现有正式数据。
- 为数据库、对象存储和环境秘密建立备份与恢复说明。
- Resend、未来腾讯云邮件、当前托管和未来服务器继续通过适配器解耦。

## 14. 性能规则

- 图片生成多尺寸版本并使用合适尺寸，不在列表加载原始大图。
- 视频列表只加载封面，进入详情后再加载播放器元数据。
- 首屏以外图片延迟加载。
- 列表、报名和审计日志使用分页。
- 动画仅使用合成友好属性并避免同时播放大量元素。
- 页面切换不重复请求不变数据，使用缓存与后台刷新。
- 设定性能验收：主要工作台交互不因动画延迟操作，低性能设备可关闭全部非必要动效。

## 15. 测试与验收策略

### 15.1 测试层次

1. 单元测试：状态、权限、排序、排期、版本、收藏和指标计算。
2. API 集成测试：跨角色越权、状态流转、重复提交和失败恢复。
3. 浏览器端到端测试：真实点击、表单、上传、审核、报名、导出和浏览器前进后退。
4. 视觉回归：公共主页、学生、企业、JA 主要页面和关键状态截图。
5. 可访问性：键盘、焦点、对比度、减少动效和语义检查。

### 15.2 关键业务闭环

- 企业创建活动 → 上传封面 → JA 审核 → 学生端原图展示 → 学生填写报名 → 企业查看 → 企业通过 → 学生通知与日历 → 活动完成 → 成长时间轴出现 JA 认证。
- 企业发布内容 → JA 审核 → 公开阅读/播放 → 学生点赞评论 → 企业回复 → 学生收到通知。
- 企业发布岗位 → 学生筛选 → 进入企业主页 → 查看岗位详情 → 复制或打开简历邮箱。
- JA 发布活动 → 学生报名 → JA 审核报名 → 学生成长时间轴认证。
- 发布内容定时上线/下线 → 通知与目录同步 → 版本历史可回滚。
- 管理员角色变化 → 权限立即生效 → 高风险操作和导出可审计。

## 16. 实施顺序与阶段验收

本设计确认后，不并行粗改所有页面，按以下顺序逐阶段实施：

### 阶段 A：设计系统和导航基础

- 拆分通用组件和 motion tokens。
- 重构工作台稳定框架、URL、前进后退、焦点和滚动恢复。
- 统一按钮、表单、弹窗、侧栏、加载、通知和错误状态。
- 不改变业务数据。

验收后再进入下一阶段。

### 阶段 B：公共主页和公开目录

- 修复真实数据、全部轮播、三栏内容和准确深链接。
- 统一企业主页、岗位、活动和内容详情。

### 阶段 C：学生端

- 依次完成总览、机会、收藏、活动、日历、内容、成长主页。
- 每个模块单独完成功能、动效和测试后再做下一模块。

### 阶段 D：企业端

- 依次完成工作台、发布中心、排期与版本、报名、互动、画像、分析。

### 阶段 E：JA 端

- 依次完成看板、三类审核、JA 发布、排序、认证、互动诚信、权限、分析和审计。

### 阶段 F：全链路验收

- 执行全部业务闭环、性能、无障碍、视觉回归和部署兼容检查。
- 本轮仍不做手机版专项重构和 PWA。

## 17. 用户审核清单

用户需要一次性确认以下内容后再开始实现：

1. 统一动效强度和页面切换方向。
2. 公共主页轮播及三类栏目结构。
3. 学生端收藏、活动日历、简历识别和成长时间轴规则。
4. 企业统一五步发布流程、排期、版本和报名数据结构。
5. JA 三类审核的准确边界及 JA 内容直接发布规则。
6. JA 五种管理员角色和权限范围。
7. 企业和 JA 高级分析的第一阶段指标。
8. 移动端专项适配与 PWA 均不在本轮。

## 18. 参考规范

- Atlassian Design System Motion：统一 motion tokens、入口与退出、减少动效。
- IBM Carbon Design System：productive/expressive motion、按钮、表单、进度指示器、数据表和文件上传。
- Material Design 3：状态层、组件反馈和品牌化动效。
- W3C WCAG 2.2 与 WAI Carousel Pattern：焦点、自动播放暂停、键盘和减少动态效果。
- MDN View Transition API：页面和共享元素过渡及兼容回退。
