# 学生机会入口与校园授权修复验收

日期：2026-11-18

## 正式环境定位

- 正式数据库中合作学校为 0，学籍记录和业务任命记录均为空。学生没有可选学校是因为目录尚未开通，不能通过任意填写学校获得管理权限。
- 公开目录的 3 条岗位均未包含可选的 `tags` 字段。学生页将原始数据直接断言为 Job 并执行 `tags.join()`，导致机会页进入全页错误界面；公开列表此前有默认值处理，未触发相同故障。
- 补充浏览器回归时发现筛选 URL 的首屏客户端状态与服务端不一致，并存在离开机会页后仍改写地址的风险。

## 修复

1. 学生端和公开岗位页面共用 `normalizePublicJob`，兼容缺省、空值、历史文本列表；不修改原有数据库记录。
2. 筛选状态在客户端挂载后恢复，只在仍位于机会页时同步地址，保持刷新和前进后退可用。
3. 校园页显示学校未开通、待核验、已核验的实际状态和后续操作。
4. 后台“学校与任命”明确四步流程，提供“前往本校学生核验”入口。保持仅技术管理员可开通学校和任命的权限规则。

## 管理员开通步骤

1. 登录 `/ja-login`，进入 `/operations?access=owner` 的“学校与任命”，添加合作学校。
2. 对方使用学生账号进入 `/campus`，刷新学校列表，选择学校并申请加入。
3. 管理员进入“本校学生”，选择学校后核验学生。
4. 返回“学校与任命”，填写其注册邮箱，选择“星光伙伴”和学校，确认任命。

个人资料中的学校文本不等同于核验学籍；已核验学校不能由学生自行覆盖。正式学校和伙伴由管理员按真实资料开通，本次不自动插入虚构学校或授予实际账号权限。
